# FR_ML

주식 수익률과 팩터 특징을 함께 사용하는 **딥러닝 시계열 예측·투자성과 연구** 프로젝트입니다. Transformer, Autoformer, Informer, iTransformer, PatchTST 계열을 공통 데이터 흐름에서 비교하고 수익성 중심 실험을 수행합니다.


## 실험 결과

**PROFIT(Patch-RevIn Oriented Finance Integrated Transformer)**을 제안합니다. RevIN과 시간 패치·계절성·변수 간 상호작용을 결합해 한국·일본·미국·유럽의 주가 시계열을 예측합니다. 입력 52주에서 미래 13주를 예측하며, 가용 패널 표본의 누적 수에 따라 학습·검증·테스트를 60/20/20으로 나누는 설정입니다.

| 시장 | PatchTST MAE | PROFIT MAE | MAE 상대 감소율¹ | PatchTST MSE | PROFIT MSE |
|---|---:|---:|---:|---:|---:|
| 한국 | 0.1291 | 0.1270 | 1.63% | 0.0467 | 0.0457 |
| 일본 | 0.0840 | 0.0836 | 0.48% | 0.0144 | 0.0142 |
| 미국 | 0.1355 | 0.1335 | 1.48% | 0.0470 | 0.0464 |
| 유럽 | 0.0807 | 0.0805 | 0.25% | 0.0132 | 0.0129 |

¹ 표 6의 반올림 표시값으로 `1 − MAE(PROFIT)/MAE(PatchTST)`를 계산했습니다. 네 시장의 단순 평균은 **약 0.96%**입니다. 논문 결론의 “평균 MAE 5.3% 감소”와 일치하지 않으므로, 다른 집계 방식·원시 실험값·버전 차이 여부를 확인하기 전까지 5.3%를 대표 성과로 사용하지 않습니다.

모든 지표·모든 구조에서 우월한 것은 아닙니다. 유럽 MAPE는 PROFIT 0.0851, PatchTST 0.0848로 PatchTST가 낮습니다. 표 7의 일본 절제 실험에서는 `RevIN + Stage 1,3`의 MAE **0.0826**이 전체 단계의 **0.0836**보다 낮아, 계절성 단계의 효용이 시장마다 다를 수 있음을 보여줍니다.

표의 오차는 논문의 평가 전처리·스케일에 따른 값이며 원수익률의 %p나 투자수익률이 아닙니다. 기본 `train.py`의 비교 모형과 `test_profit_ts.py`의 확장 구조를 구분하고, 현재 config의 재현 여부를 별도로 확인해야 합니다. 거래비용을 반영한 투자 초과성과 검증으로 해석하지 않습니다.

## 데이터 흐름

```text
종목별 수익률 + 가치·규모·모멘텀·투자·수익성 팩터
  → 수익률 누적으로 가격형 시계열 구성
  → 종목별 시점 정렬·이동 구간 샘플
  → 시계열 모형 학습·검증·테스트
  → 예측 오차 및 투자성과 분석
```

## 구조

| 경로 | 역할 |
|---|---|
| `train.py` | 공통 학습기·기본 모형 비교 |
| `test_profit.py`, `test_profit_run_all_structure.py`, `test_profit_ts.py` | 수익성·구조별 확장 실험 |
| `src/dataset.py` | 종목·시간 구간 데이터셋 |
| `src/models/`, `src/layers/` | 모형·레이어 |
| `src/utils/`, `src/norm.py` | 지표·학습·정규화 보조 |
| `config.ini` | 시계열 길이·모형·학습 설정 |
| 학위논문 PDF | 연구 배경·방법 설명 |

파일명의 `test_profit`은 연구 평가 스크립트이며 소프트웨어 단위 테스트를 뜻하지 않습니다.

## 입력·텐서 형상

기본 `train.py`는 `data/korea/returns.parquet`와 같은 폴더의 `value`, `size`, `momentum`, `investment`, `profitability` Parquet를 읽습니다. 각 표의 날짜 인덱스와 종목 열을 맞춰야 합니다. 마지막 채널은 예측 대상 시계열입니다.

현재 config의 `seq_len=52`, `label_len=13`, `pred_len=13`, 팩터 5개와 대상 1개를 가정하면 배치 형상은 다음과 같습니다.

| 텐서 | 형상 | 의미 |
|---|---|---|
| `x` | `[B, 52, 6]` | 과거 입력 구간 |
| `y` | `[B, 26, 6]` | 겹치는 label 구간 13 + 예측 구간 13 |
| `x_mark` | `[B, 52, 2]` | 월·일 시간 특징 |
| `y_mark` | `[B, 26, 2]` | 출력 구간의 시간 특징 |
| MS 모드의 손실 대상 | `[B, 13, 1]` | 마지막 채널의 미래 13개 관측값 |

여기서 B는 배치 크기이며, 52·13을 달력상 기간으로 해석하려면 원천 자료의 주기를 확인해야 합니다. 모델별 출력 채널·decoder 입력 계약은 실제 구현과 일치시켜야 합니다.

## 설치·실행

```bash
python -m pip install -r requirements.txt
```

Parquet 엔진 등 추가 직접 의존성이 필요할 수 있습니다. PyTorch의 GPU 환경도 사용 장치에 맞게 준비하세요.

입력·경로·config를 준비한 뒤 실행합니다.

```bash
python train.py
python test_profit_ts.py --country korea --config config.ini --data_apath data --check_apath checkpoints --save_apath logs
```

기본 `train.py`는 모형 목록과 국가를 소스에서 지정합니다. CLI 인자로 임의 모형을 선택하는 구조로 오해하지 마세요. 확장 실험은 `--skip_col` 등 별도 옵션을 사용합니다. 실제 저장 경로와 재학습·기존 체크포인트 로딩 분기도 확인해야 합니다.

## 연구상 주의점

- 데이터셋은 가용 관측 수를 고려해 시간 범위를 나누므로 단순히 행의 60/20/20 분할과 동일하다고 가정하지 않습니다.
- 학습·검증·테스트의 `std_scale`·채널 복원·클리핑 설정을 비교해야 합니다.
- decoder에 전달되는 `y`의 미래 값을 모형이 어떻게 사용하는지 확인하고, 예측에 미래 관측이 유입되지 않도록 모형별 검증이 필요합니다.
- 예측 오차 개선과 비용 차감 투자성과 개선은 별도로 평가해야 합니다. 포트폴리오 선택·중복 구간·상장폐지·거래비용을 고려하세요.

코드 구조와 연구 가설을 비교하는 출발점으로 활용할 수 있으며, 이 README는 독립 성과 재현 결과를 제공하지 않습니다. 원천 금융자료·논문·제3자 모형 코드의 이용 조건을 각각 확인하세요.
